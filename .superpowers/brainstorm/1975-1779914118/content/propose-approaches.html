Proposed Architectural Approaches

Selected Option C: Microsoft Identity + JWT Token Authentication

1

Built-in ASP.NET Identity Endpoints (Recommended)

Uses .MapIdentityApi<IdentityUser<Guid>>(). Automatically exposes standard `/register`, `/login`, and `/refresh` endpoints using built-in high-security controllers.

✔ Easy setup, zero boilerplate, Microsoft maintained, secure refresh tokens.
✘ Fixed JSON request/response formats.
2

Custom AuthController & JWT Services

Write our own AuthController utilizing UserManager and generate JWTs manually using JwtSecurityTokenHandler.

✔ Full customizability of requests, responses, and token claims.
✘ Writing security-sensitive token logic, more code to maintain.
3

External Identity Provider (Auth0 / Keycloak)

Delegate authentication entirely to an external service using OpenID Connect (OIDC) protocols.

✔ Absolute isolation of credentials, professional-grade SSO.
✘ Heavy infrastructure dependency, config complexity, potential subscription cost.
