Section 3: Controller Security & User Filtering

Enforcing the Authorize attribute and isolating queries per logged-in user

AnalysisSessionsController.cs (Security Architecture)
[Authorize]
[ApiController]
[Route("api/analysis-sessions")]
public class AnalysisSessionsController(...) : ControllerBase
{
    
// Helper property to extract current authenticated User's Guid
    private Guid CurrentUserId => Guid.Parse(
        User.FindFirstValue(ClaimTypes.NameIdentifier)!
    );

    [HttpGet]
    public async Task<IActionResult> GetSessions(CancellationToken token)
    {
        var sessions = await _dbContext.AnalysisSessions
            .Where(x => x.UserId == CurrentUserId)
// Strict isolation filter

            .OrderByDescending(x => x.CreatedAt)
            .ToListAsync(token);
        return Ok(sessions);
    }

    [HttpGet("{id:guid}")]
    public async Task<IActionResult> GetSession(Guid id, CancellationToken token)
    {
        var session = await _dbContext.AnalysisSessions
            .FirstOrDefaultAsync(x => x.Id == id && x.UserId == CurrentUserId, token);
        if (session is null) return NotFound();
// Prevents user enumeration

        return Ok(session);
    }
}
Security Hardening and Edge Cases
Crucial Protections:
- Any attempt to view, start, approve, reject, or upload metrics to a session by its GUID will be checked against the logged-in user's UserId.
- If a session belongs to a different user, the API will return a 404 NotFound immediately, preventing external parties from discovering if a session exists (enumeration protection).
- Background orchestrator services work within the system context, but user decisions (approvals/rejections) are verified for the current caller.
